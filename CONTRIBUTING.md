# Working together on this repository

Every designer works in their **own clone** inside their **own EDA box**. Git (this GitHub
repository) is the only way work moves between people. Never share one working folder.

## One-time per person
```bash
# Ubuntu window
sudo apt install -y git-lfs gh
git lfs install
gh auth login                     # GitHub.com > HTTPS > login with a web browser
gh auth setup-git
cd ~/eda/designs
gh repo clone <owner>/analog-flow
cd analog-flow
flow/designinit.sh > ~/eda/designs/.designinit && docker restart eda_$USER
```

## Every change
```bash
# Ubuntu window
cd ~/eda/designs/analog-flow
git switch main && git pull                    # start from the latest verified state
git switch -c <you>/<cell>-<what>              # e.g. nithx/inv-wider-pmos
git lfs lock cells/<cell>/layout/<cell>.gds    # BEFORE editing a layout (GDS cannot be merged)
#   ... edit in xschem / KLayout, run `make CELLS=<cell>` inside the box until it PASSes ...
git add -A && git commit -m "<cell>: <what changed>"
git push -u origin HEAD
gh pr create --fill                            # CI runs the changed cells on the pull request
#   ... CI green + review -> merge on GitHub ...
git lfs unlock cells/<cell>/layout/<cell>.gds
```

## PDK blocks without xschem symbols (IO pads, ESD clamps)
Shared symbols live in `cells/_io/schematic/` (folders starting with `_` are found by xschem but
are never run as cells). Generate them from the PDK netlist so pins always match:
```bash
# EDA box
F=$PDK_ROOT/$PDK/libs.ref/sky130_fd_io/spice/sky130_fd_io.spice
python3 flow/lib/sym_from_subckt.py --netlist $F --list 'clamp|pad'
python3 flow/lib/sym_from_subckt.py --netlist $F --out cells/_io/schematic sky130_fd_io__top_lvclamp
```
A testbench that uses such a symbol must include the PDK netlist once, in its code block:
`tcleval(.include $env(PDK_ROOT)/$env(PDK)/libs.ref/sky130_fd_io/spice/sky130_fd_io.spice)`.
Do not put these symbols in a cell that runs LVS yet: the flow has no layout-side handling for them.

## Tiny Tapeout repositories
If this repository has an `info.yaml`, it is a Tiny Tapeout project. See `flow/tt/README.md`.
Before committing anything you may submit: `make tt` (EDA box), then commit `gds/`, `lef/`
and `src/project.v` together with your layout. Never edit `.github/workflows/gds.yaml` or
`docs.yaml`, never move or resize the template pins, never use metal 5.

## Rules
1. **One owner per cell at a time**, made visible by the GDS lock (`git lfs locks` lists them).
2. **Merge only when CI is green.** CI also re-verifies every parent cell that uses a changed cell.
3. **Only sources are committed** (`schematic/`, `layout/`, `sim/specs.txt`, flow code).
   Results are regenerated by `make` and attached to each CI run as artifacts.
4. **Changes to `flow/`, `flow.conf` or `.github/`** re-run every cell in CI; make them in their
   own pull request.
5. Do not rename or retag the EDA image (`FLOW_IMAGE` in `flow.conf`) without re-running all
   cells: results are only comparable within one image + PDK version.
